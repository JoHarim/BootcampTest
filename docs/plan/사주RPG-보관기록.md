### ⛔ 되살리면 안 되는 것 — 사주 엔진 전체 (`saju-engine.ts`)

1. **시간대 60분 계통 오차 (치명).** lunar-javascript의 절기표는 베이징시(UTC+8)인데
   `saju-engine.ts:520`에서 한국 벽시계 시각을 그대로 투입한다. 시차 변환 코드가 0줄.
   → 한국 출생자 **모든 절입 경계가 정확히 60분 조기**.
   실증: 2024-02-04 17:00 KST → 이것은 `甲辰년 丙寅월`(편관격), 정답은 `癸卯년 乙丑월`(양인격).
   **년주·월주·격국·직업이 통째로 뒤바뀐다.**
2. **세운 기준 혼선.** `saju-engine.ts:655`가 `getYearInGanZhi()`(음력 설날 기준)를 쓴다.
   입춘 기준이어야 맞다. 매년 입춘~설날 구간(2026년 13일) 세운이 1년 어긋남.
   같은 함수 안에서 월운은 절기 기반이라 **기준이 뒤섞여 있다.**
3. **지장간 표 내부 불일치.** `saju-engine.ts:124-137`에서 사왕지 4개(子卯酉午)의 여기·중기 누락.
   나머지 8지지는 3글자를 다 넣어, 지지당 지장간 기여가 0.5~1.5로 3배 편향 → 오행 점수 왜곡.
4. **진태양시·경도 보정 없음, 음력 입력 없음.** 한국 사주 앱으로는 결격.
5. **테스트 0건.** 3,970줄에 회귀 테스트가 없어 위 결함이 살아남았다.
   > ⚠️ 개발 기록에 적힌 "엔진 테스트 13건 / 시뮬 78/78 완주"는 **일회성 스크립트를 돌리고 삭제**한 것이라
   > 저장소에 없다. 재현 불가. 앞으로는 검증 스크립트를 반드시 커밋할 것 — 이 사고의 직접 원인.

정확한 부분(참고): 십성 판정(`tenGodOf`), 삼합군·천을귀인 표, 대운 순역은 표준과 일치.

## 4. 처리 방침

- **코드**: 삭제하지 않는다. 위 6개 부품의 원본이라 이식이 끝날 때까지 보존.
- **라이브 URL** (`/rpg`): 사주가 틀린 상태로 공개돼 있으므로, B 배포 시 **교체하거나 내린다.**
  (`/saju` 플래너와 `/` 럭키런은 별개 트랙이라 유지)
- **문서**: `docs/plan/rpg-design.md` 와 변경 제안서 4건은 밸런스 수치의 근거 기록으로 남긴다.
  단, **명리 계산 부분의 설계 서술은 틀렸다** — 이식 시 B의 `src/engine/`을 정답으로 삼을 것.

## 5. 배운 것 (다음 프로젝트에 적용)

1. **외부 라이브러리의 기준계(시간대·좌표계)를 반드시 확인한다.** 초 단위로 정밀해 보여도
   기준이 다르면 통째로 틀린다. 이번엔 "절기표가 베이징시"라는 한 줄을 확인 안 해 60분이 어긋났다.
2. **검증 스크립트는 커밋한다.** 돌리고 지우면 "검증했다"는 말만 남고 회귀는 못 잡는다.
3. **도메인 정확도가 핵심인 제품은 도메인 테스트부터 짠다.** B는 절입 순간 ±3분에서 월지가
   넘어가는지를 자동 검사한다 — 그래서 안 틀렸다.
